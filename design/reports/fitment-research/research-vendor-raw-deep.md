# Deep pass over RAW vendor files for vehicle fitment (local, read-only, 2026-10-06)

Tree: ~/Platinum Wheels Vendor Data/Individual Vendors/. Non-image files: Auto Country 105 (16 MB), DAI 117 (11 MB), PRO WHEELS 417 (69 MB, 303 of them raw API page JSONs), Vertex 68 (8 MB), Wheel Works 47 (48 MB, 28 saved HTML search pages). No zip/gz/pkl/db anywhere; one xlsx (DAI_site_products_not_in_files.xlsx, no vehicle text). ~99k image files not read. Scripts used: scratchpad/deep/*.py.

Method: every CSV cell and every json/html/body/js/xml/txt/jsonl file scanned for the 47 makes in vehicles.csv (+ aliases VW, Chevy, Hyu...), 843 model names (len>=5), fitment keywords, OE tire tokens (MO, N0, AO, RO1, *, HL...), TPMS 315/433/MHz, thread, hub bore, plus JSON key census of all 340 json files.

## Findings (vendor, file, field, count, what it gives)

1. Vertex wheels (public Shopify products.json): wheels.csv `fitment` / `raw_tags`, `_working/build/products_p*.json` tags. 22 of 22 wheels (all OE Stance), tags `fitment:Make:Year:Model:Trim`, 82 fitment tags, 18 `make:` tags. 11 make/model/year combos, 9 models, 17 trim strings, 3 makes (Acura, Audi, Honda), years 2024-2025. Gives: wheel bolt pattern per vehicle (5x112 Audi A3/A4/A4 Allroad; 5x120 MDX/TLX/Integra Type S; 5x114.3 RDX/ADX/Accord/Integra base). Wheel's own bore/offset only, NOT vehicle data. Maps to vehicles.csv: 8 of 9 model names match exactly (A4 Allroad vs finder 'A4 allroad' is case only; all 9 resolve). Other 467 Vertex products (tires 466, 1 tire fee): tags only `dealer-discount`, `OTFTAX`, `b2b-only`: zero vehicle tags. Tire descriptions mention only vehicle CLASS (SUV 92, sedan 73, crossover 63, light truck 45): not usable. Tag trims look like Wheel-Size-style trim strings (B9 Facelift, YD4); licensing provenance unknown.
2. DAI "ART Replica" wheel listing pages (raw saved HTML `_working/phase1/cat21.body`, `_working/phase2/cat21.body`, product page `phase2/prod_wheel.body`): Notes tab text `<MAKE> COMPATIBLE`. Only 48 products saved from 652 ART rows (195 designs). 29 rows carry a note (24 in phase1, 5 in phase2): Audi 9 (+2 'Audi / Volkswagen'), Jeep 6, Toyota/Lexus 3 (+1 Toyota), Dodge 1, BMW 1, Mercedes 1, Kia 1, Tesla 1, RAM 1 (+ 'low profile weights'), Acura 1, plus 1 'Toyota/Lexus OE Radius bolts only' hardware note. 15 designs. Gives MAKE only (no model/year) + the replica's bolt/bore/diameter/width/offset (e.g. REPLICA 133 BMW 5x120 bore 72.6; REPLICA 143 Kia 5x114.3; REPLICA 183 Acura 5x114.3). Every (make, bolt pattern) pair already exists in vehicle-fitment*.csv: adds nothing. Remaining ~637 ART rows' notes were never captured (needs the DAI dealer pages).
3. DAI accessory titles (DAI_product_list.csv, nut_list, accessories_*.csv, site_listing.json): 44 distinct descriptions / 82 rows name a make. Facts = lug thread by MAKE: Honda 12x1.5 (19mm) and 14x1.5 (22mm); Ram 14x1.5 and 9/16-18; Ford 12x1.5, 14x1.5, 14x2.0; Mazda 12x1.5; Land Rover 14x1.5; Tesla 14x1.5; Dodge Caravan 12x1.5 (the only MODEL-specific nut); Genesis GV80 14x1.5 bolt kit (6 splines); TPMS snap-in valve "many Chrysler Ford + 15-16 Hyundai Sonata, 14-16 Kia Soul"; TPMS Tesla 3/Y 2021+ BLE (3 rows). scripts/data/vehicle-thread-generations.csv is currently header-only (0 rows) so all of this is new, but it is make-level hints + 2 models, not model-year rows. Auto Country adds 3 lug-nut titles (Jeep 1/2" spike install kit x2, Ford 14x1.5).
4. PRO WHEELS tires.csv: OE approval tokens in titles: 5 x `MO` (Mercedes) + 2 x `N0` (Porsche) on Yokohama Advan Sport V105 (7 rows). Maker-level only, no model. `HL` (13) = Nexen/Goodyear model suffix, not OE. No other vendor tire carries OE tokens (DAI, AC, WW, Vertex: 0). 24 `BluEarth*Winter` asterisks are the model name, not BMW star.
5. PRO WHEELS wheels/tires raw API pages (21,178 wheels, 6,233 tires): field allowlist only (id, sku, brand, name, width, diameter, offset, cb, pcd1/2, color, finish, load, season, inventory, photo, price...). No vehicle field. The one fully captured wheel record (`phase1/api-wheel-KM5226...json`) has 107 keys incl. `info`, `metadata`, `spec`, none vehicle. 822 wheel rows are replicas (ART Replica 588, Performance Replicas 234; 220 designs) named by design number only. PRO WHEELS JS shows `POST wheelsapi.com/api/get-wheels-by-vehicle` {make,year,model,submodel,diameter} (returns `oe` wheel spec) and `POST /api/verify-fittment` {vehicleKey,sku}; list rows can carry `will_fit` boolean; the endpoint that lists years/makes/models is NOT in the saved chunks.
6. Auto Country: `nero/*` endpoints in `_working/phase1/js_1f0vkb6uu2q8r.body` (GET /nero/years, makes/{y}, models/{y}/{make}, sub-model/{y}/{make}/{model}, options/{y}/{make}/{model}/{sub}; POST /nero/vehicle-ranges). Output schema decoded from `js_04si9o0ex1czz.body`: per vehicle, tier `oem` per axle (allAxles or front/rear) with wheel diameter min/max, width min/max, bolt pattern min/max, offset min/max, and tire diameter + metric width min/max; plus `vehicles[].fitments[{option,diameter,id}]` and `lifts`. So it WOULD give OE bolt pattern, wheel size, offset and tire diameter/width per Y/M/M/submodel, incl. staggered axles; no hub bore, thread or TPMS. `/accessory/find-by-vehicle` (Bearer token, logged in) would map vehicle -> lug nut / hub ring / center cap SKUs (thread + hub-ring ID derivable from titles). Nothing was ever called. Tires: `fitment_note` key empty in all 13 captured rows. 326 raw accessory rows carry no vehicle field.
7. Wheel Works: 696 tires, vehicletype 'ANY' x696, vehiclemodel 'ANY' x696, make_year '' x696, inflation '' x696 (verified across all 6,802 form fields in 17 saved HTML pages). 2 wheels (RIM17/RIM18) no vehicle. Zero.
8. DAI site scaffolding: `phase2/preferences.body` lists 73 vehicle makes (account preference checkboxes; 26 not in vehicles.csv e.g. Aston Martin, Ferrari, Lotus, Oldsmobile, Plymouth, SRT); `home.body`/product pages carry the YMM widget with the year list 1992-2027 only; ajax/GetMakes|GetModels|GetSubModels|GetOptions.php and `ShowApplication.php?reference=<SKU>&type=wheels` (the "Applications" tab; recon note: "database of 100,000 applications") never called. `phase2/medias.body` lists dealer PDF catalogues per make (download.php?file=Honda.pdf, Toyota, Ford, Nissan, Hyundai, Kia, Mazda, Subaru, Mitsubishi, Jeep, Chrysler-Dodge, Chevrolet-GMC, VW, Jaguar, Land Rover, each also `_Blank.pdf` no-price) under target=promotions/dealers, not downloaded: probably OE-replica wheel promos per make; unknown content.
9. TPMS / frequency: no 315 or 433 MHz statement for any vehicle anywhere. 2 universal "dual band / dual freq" sensors (Bosch, TXK002). DAI wheels carry `TPMS` Yes 1,193 / No 146 (wheel-level compatibility, not vehicle). Seat types (Conical 1,016, Radius R12/13/14 264, Flat OE 81) are wheel hardware, not vehicle.
10. False positives: 1,244 PW wheels / 1,571 PW tires / 626 AC wheels etc. matched vehicle model words (Maverick, Charger, Wrangler, Legacy, Renegade, Fusion, Element...) but all are product model names. Wheel Works tires 'Tacoma H/T' and 'S2000' are tire model names.

## Quantified NEW fitment vs scripts/data/vehicle-fitment*.csv
- Bolt pattern: Acura ADX 2025 = 5x114.3 (Vertex): the one model in the finder's no-data list that any vendor file touches (ADX 2025-2027, so 3 model-years incl. nearest-year). Audi A4 and A4 Allroad 2025 (5x112) just turn nearest-year into exact-year (existing rows end at 2023). Integra 2024 shows a TRIM split the finder lacks: Type S 5x120 vs base 5x114.3 (existing Integra 2023-2025 rows say 5x114.3 only, so Type S is wrong today). Everything else (MDX, RDX, TLX, A3, Accord) agrees with existing rows. Net: about 3 model-years + 1 trim exception; 0 new bolt patterns.
- Tire size: 0. Offset: 0 (only replica/wheel's own). Hub bore: 0 usable (vendor bores are the wheel's). Thread: make-level hints for 8 makes and 2 models (Dodge Caravan, Genesis GV80), 0 model-year rows. TPMS frequency: 0.
- Total: negligible (~3 model-years of 7,528 offered; 22 wheels flaggable "fits <vehicle>"). Not a substitute for the hand-kept sheets.
