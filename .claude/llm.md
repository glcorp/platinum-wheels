# .claude/

## Purpose
Claude Code's project-scoped configuration. It carries the one authoring rule that auto-loads on every
`src/**/*.tsx` edit, the two impeccable design-detector hooks, the dev-server launch config, the four
impeccable agent definitions, and the vendored skill copies. Delete it and every session loses the UI
non-negotiables, the design gates and the pinned skill versions at once; since D55 a commit can restore
it, but only back to 2026-09-21.

## Owns
- [`rules/`](rules/llm.md) — path-scoped authoring rules; today only `ui.md`.
- [`agents/`](agents/llm.md) — four impeccable agent definitions.
- [`skills/`](skills/llm.md) — vendored skill copies; six pinned in `skills-lock.json`, two not.
- [`launch.json`](launch.json) — two dev servers: `app` = `npm run dev` on port 3000 (`launch.json:5-8`)
  and `design-baseline` = `npx --yes serve design -l 4000` (`launch.json:11-14`; `design/serve.json` supplies the
  rewrites, D36).
- [`settings.json`](settings.json) — impeccable hooks only: `PostToolUse` on `Edit|Write`
  (5s) and `Stop` (30s), both running `${CLAUDE_PROJECT_DIR}/.claude/skills/impeccable/scripts/impeccable
  hook` behind a file-exists guard (`settings.json:4-28`). Renamed from `settings.local.json` and
  committed by D55(3) so the gates reach the co-founder; the `.local` name stays gitignored for genuine
  per-machine overrides.
- `.DS_Store` — macOS artefact, not configuration.

## Rules
- **`launch.json` resolves correctly when the session starts in this directory.** The failure recorded at
  `HANDOFF.md` §8.16 came from a session started in the wrong directory. Verified 2026-09-20: `preview_start`
  read the `design-baseline` entry and reported only that port 4000 was already in use (root `llm.md` D36).
  If a server is already running on the port, `navigate` to the `localhost` URL instead of starting another.
- Baseline URLs from `design-baseline` are **extensionless** — `npx serve` strips `.html`, so
  `http://localhost:4000/home-desktop`, not `/home-desktop.html` (`HANDOFF.md` §1, §8.13).
- Both hooks are a no-op when `.claude/skills/impeccable/scripts/impeccable` is absent — the
  `[ ! -f … ] ||` guard (`settings.json:10`, `:22`). Removing that skill disables the design gates
  without any error.
- **`skills/impeccable/scripts/bin/` is gitignored** (D55(2)): the 12 MB binary there is `darwin-arm64`
  only. The launcher `scripts/impeccable` *is* committed and resolves a binary from `$IMPECCABLE_BIN`,
  `~/.impeccable/bin`, the version-pinned cache or `PATH`, so a fresh clone runs the hooks once a binary
  exists on that machine — and no-ops silently until then.
- Hook consent is already recorded as accepted at `.impeccable/config.local.json:2-3`. `.impeccable/` is
  deliberately outside the library's folder map (root `llm.md:155-157`).
- `.claude/skills/*` are **vendored copies**, not references. Do not edit them; re-install to update
  ([`skills/llm.md`](skills/llm.md)).
- Root `CLAUDE.md` is exactly two imports: `@AGENTS.md` and `@llm.md` (`CLAUDE.md:1-2`). `AGENTS.md` is
  written by `next dev` — **do not edit it** (root `llm.md:183-184`).
- Anything added, renamed or re-purposed in here updates this file in the same change (root
  `llm.md:19-21`).

- **Depends on:** `.claude/skills/impeccable/scripts/impeccable` (both hooks);
  `.impeccable/config.local.json` (hook consent); `package.json`'s `dev` script and `design/assets/`
  (the two `launch.json` entries); root `llm.md` and `AGENTS.md` (reached through `CLAUDE.md:1-2`).
- **Depended on by:** every session, via `CLAUDE.md`; every `src/**/*.tsx` edit, via
  `rules/ui.md`'s `paths:` frontmatter (`.claude/rules/ui.md:2`); the parity workflow, which measures the
  app against the `:4000` baseline this folder configures (`HANDOFF.md` §1).

## Don't
- Don't start a second server when `preview_start` reports the port in use — `navigate` to the running one.
- Don't append `.html` to a `:4000` baseline URL (`HANDOFF.md` §1, §8.13).
- Don't edit `AGENTS.md`; it is regenerated by `next dev` (root `llm.md:183-184`).
- Don't hand-edit files under `skills/` or `agents/` — both are installed copies; see their `llm.md`.
- Don't put authoring rules in `settings.json`. Rules go in `rules/` with `paths:` frontmatter
  (`.claude/rules/ui.md:1-3`); `settings.json` is hooks only.
- Don't commit a `settings.local.json`. It is gitignored on purpose (D55(3)) — anything that must reach
  the co-founder goes in `settings.json`.
